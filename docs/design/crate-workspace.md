# 当前模块职责与依赖

本文按角色描述当前架构，不规定语言、包数量或源码布局。现有目录名保留为文档入口；具体实现映射见[实现指南](../develop/rust-workspace.md)。[Runtime 架构](runtime-core-architecture.md)的首版范围已按执行约定实施；未来类型和管理能力仍未交付。

## 职责与允许依赖

| 角色 | 拥有的合同 | 依赖角色 |
|---|---|---|
| 持久值 | 会话配置与元信息的数据含义 | 无运行依赖 |
| Runtime 合同 | 具体连接的命令、事实交付、错误和公共身份转换 | 不依赖具体适配或外部协议 |
| Journal | 原子元信息、顺序追加、历史读取和尾部修复 | 持久值 |
| 事件核心与处理器交付 | 唯一提交入口、不可变事件、实时分发及有界消费者 | Runtime 合同、Journal |
| Codex 适配 | 原生服务、会话 Attachment、准入、取消和事实归一化 | Runtime 合同，不读 Journal、处理器或外部协议状态 |
| Session 管理 | 名称预留、创建回滚、绑定和生命周期协调、查询 | 持久值、Runtime、Journal和事件核心 |
| 外部协议 | 参数、响应、错误编码和实时订阅 | Session 管理与命令错误合同 |
| 系统组装 | 配置、具体运行实例、处理器和退出协调 | 对外角色及具体适配 |

调用从组装和外部协议进入 Session 管理，再到运行适配或存储与事件角色。Runtime 合同不反向选择 Codex；适配不能生成已提交公共事件。Session 通过 Runtime 的打开、Attachment 和关闭合同编排；生产依赖不得到达 Codex 或官方 SDK。恢复中的私有证据校验由适配方完成，通用层只校验公共结构、身份和顺序。类型目录由组装注入，Session 层不硬编码类型名称。

事件提交与处理器交付共同维护提交后分发次序。只有核心可以把候选事实变为已提交事件，处理器不能跳过提交、修改身份或改变 Journal 顺序。持久值只表达实际保存的数据，不拥有共享可变运行状态。

## 构造与连接

组装先构造运行实例，不启动原生服务，再交给 Session 管理协调按需激活。处理器在会话元信息提交后才启用。超时打开仍保留名称和资源所有权，直到迟到操作结算或确认释放。

处理器命令绑定原 Attachment。主机、连接和取消代际检查由适配负责；恢复不把旧命令指向新连接。Session 保留事件快照与订阅能力，但适配只交付归一化事实，不取得提交核心的可变状态。

一个 Attachment 的事实按顺序提交。独立慢处理器不阻塞其他健康消费者；持续共享传输饱和仍可能影响同服务其他会话。错误、容量、恢复与停止的精确合同分别见[原生适配](native-runtime-connectors.md)、[处理器](../handlers.md)、[存储](../storage.md)与[外部协议](../http-api.md)。

既有实现调整及其证据保留在[实现映射记录](../develop/rust-workspace.md)，不作为模块边界必须按某种语言重建的要求。

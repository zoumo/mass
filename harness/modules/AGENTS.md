# Module 设计文档规则

本文件适用于 `harness/modules/` 及其子目录。写入授权继续遵守[上层规则](../AGENTS.md#harness-写入授权)，文档格式遵守[知识管理约定](../AGENTS.md#okf-规则)。

## 设计与实现记录分离

设计正文、专题页及 TypeSpec 注释只维护当前设计：职责、所有权、Interface、行为保证、生命周期、失败规则、设计待决事项和验收要求。

- 不得写入实现差距、完成进度、当前源码符合程度或测试与验收结果，包括“尚未实现”“实现已完成”“当前代码仍然……”等结论。
- 不得添加实现差距章节、摘要、表格或差距记录导航链接。统一查询入口放在 harness 索引和工具入口，实现事实集中维护在 implementation-gaps.md 或语言实现资料中。
- 验收场景描述应观察到的行为，不记录某次执行是否通过。设计待决事项描述尚未确认的合同，不用实现缺失充当设计待决事项。
- 设计来源可以引用源码或研究材料来解释决策依据，但不得借 sources、脚注或元数据承载实现进度和验证结果。本次任务是否允许实现、是否升级依赖等执行范围也不写入 Module 合同。

维护时先判断内容是在规定行为还是报告现状。规定行为留在 Module 合同；报告现状在获授权后更新实现记录，不为消除差距而改写设计。

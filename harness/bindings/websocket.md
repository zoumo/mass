# WebSocket 承载

本绑定承载 [JSON-RPC 业务协议](jsonrpc.md)，不定义第二套 Service、资源模型或事件格式。当前只提供 WebSocket 业务入口；HTTP Upgrade 和运维探针不构成 REST 业务 API。[^direction]

## 入口与消息

- 所有业务连接使用 `/rpc`，服务地址使用 `ws://` 或 `wss://`，版本通过每条连接的 initialize 协商。
- 每条 WebSocket 文本 message 承载一个 JSON-RPC 对象；按重组后的完整消息解析，不把 frame 等同于业务消息。[^websocket]
- 二进制消息拒绝并以 1003 关闭；非法 UTF-8 以 1007 关闭。JSON 解析或信封错误按业务协议返回 JSON-RPC 错误；消息边界仍有效时允许继续读取。
- 不使用按行分帧、Content-Length codec 或传输类型探测。新连接必须自行认证和 initialize，不能借用另一连接的初始化状态。
- Ping/Pong 用于连接存活检测，不表示 Agent 健康或工作完成；心跳、写入期限及关闭等待预算由部署明确配置，不另加业务 ping 方法。
- 客户端只连接明确 endpoint；失败时不启动本地服务、不自动发现另一个实例、不切换协议或重放请求。

## 连接与订阅隔离

客户端用一条连接处理普通 RPC，每次 Subscribe 另建一条独立 WebSocket。它们使用相同的入口、认证、initialize 和方法集，不增加“控制连接”和“事件连接”的角色握手。

每条连接最多有一个活动订阅。服务端在登记前原子预留订阅位置；并发或重复 subscribe 不能产生两个活动订阅，后来的调用返回业务 conflict，reason=subscription_already_active。原订阅终止并完成清理后，该连接可以显式重新订阅；SDK 默认关闭已结束的订阅连接，不建立连接池或自动重连。

不禁止自定义调用方在有订阅的连接上调用普通 RPC，但它自行承担该连接被驱逐时丢失响应的风险。SDK 的 Subscribe 必须使用独立连接；默认 Client.Close 关闭该客户端拥有的普通连接和全部订阅连接，Subscription.Close 只关闭自己的观察连接。

subscriptionId 只在产生它的连接内有效；unsubscribe 必须在该订阅连接发送，不在普通 RPC 连接查找或取消另一连接的订阅。直接关闭订阅连接也会释放该观察，且不发送 Session cancel/close。

订阅成功响应确认就绪。客户端需先在观察连接等到成功，再在普通连接提交输入；两条连接上的输入回执和事件没有到达顺序保证。普通连接断线不自动关闭仍健康的观察连接；SDK 整体 Close 的行为另按所有权执行。

### 慢消费者与驱逐

| 故障 | 行为 | 默认客户端的影响范围 |
|---|---|---|
| Service 的单订阅队列溢出 | 结束订阅，保留错误，可写时发送 subscription.closed | 该观察 |
| 客户端某订阅的业务消费慢 | 本地有界缓冲；溢出后明确失败并关闭该订阅连接 | 该观察 |
| 单连接写入超时或网络阻塞 | 终止连接并释放所属订阅，尽力发送 1011 Close | 该观察；不关闭其他连接 |
| 普通 RPC 连接失败 | 唤醒在途等待；无响应的副作用结果未知 | 该连接的 RPC，不取消已接纳工作 |
| 服务退出或公共网络失效 | 所有受影响连接结束 | 不宣称独立连接可以隔离公共故障 |

subscriptionId 不提供独立流控，写入成功也不证明业务消费成功。本绑定通过独立连接隔离驱逐，不引入逐流 ACK、消费额度或公平调度。终止通知和 Close frame 都可能因网络失效无法送达；活动观察未收到明确 subscription.closed 就遇到 EOF，必须报告异常，不能按“工作完成”处理。

## 认证与部署

原生客户端和 massctl 在 Upgrade 请求携带 `Authorization: Bearer <token>`；校验通过才建立连接或解析资源目标。无凭据/无效凭据返回 HTTP 401，有效凭据但无权接入返回 403；失败不建立 JSON-RPC 连接。不把 token 放入 URL、query、subprotocol、JSON-RPC 参数或日志。

有效 token 授予本实例全部 Runtime、Session、历史与操作权限；namespace 仅分组，不提供租户隔离。不互信的调用者使用独立实例。本版不新增账号、ACL、跨连接控制者选举或按资源授权。

非本机连接使用 WSS，可由受信反向代理终止 TLS；代理至服务的链路必须处于明确受信部署边界。代理须支持持续双向消息与 Upgrade，空闲期限应容纳心跳。需用实际部署链路验证首响应、后续事件、慢客户端及断线，不能仅依据源站响应头。

未配置认证仅允许显式本机单用户模式，绑定回环地址；回环不代替多用户身份隔离。存在 Origin 的 Upgrade 必须命中显式允许列表，缺少允许列表时拒绝；无 Origin 的原生客户端仍须通过所选 token 或本机信任模式。不能把 Origin 当作认证。

首版的直接连接范围是原生客户端。浏览器应用通过自己的已认证后端连接 MASS；浏览器直连的 cookie/短期凭证流程不属于本版合同，不能隐式改为 query token。

## 服务实例与数据所有权

massd 独立运行，每个实例拥有明确的监听地址和 DataDir。一个 DataDir 包含元数据、事件和恢复材料，同一时刻仅允许一个服务实例拥有写入和运行管理权。多个客户端共享服务，不直接打开服务端存储。

复用存储已有的排他写入机制：全部必要 Store 打开成功并取得写入权后，才执行 Service 启动校正、启动 Driver 或公开 ready。启动失败逆序关闭本次资源；第二个实例使用同一实际目录时明确报告 data_directory_in_use，不因端口不同或路径别名绕过，不自动更换空目录。

运行期间持有写入所有权，直到 Service 的本地工作和最终事件结算、Store 关闭完成；不能提前释放。实际锁而非 PID 或锁文件存在性决定占用，锁句柄不泄漏给 Agent 子进程。恢复遵循已有 unknown/身份验证规则，取得目录锁不证明旧外部 provider 工作已经结束。

不预设新的 Engine SDK、全局实例注册表或第三套锁。多个独立实例须使用不同地址和数据目录；不同 DataDir 也不自动保证能同时接管同一原生 Agent 会话，受支持的会话共享路径是多个客户端连接同一服务。

## 健康探针与退出

保留最小 HTTP 运维探针：

| 路径 | 响应与含义 |
|---|---|
| GET /livez | 200，仅表示进程能响应 |
| GET /readyz | 必要初始化完成且接纳业务时 200，否则 503 |

探针不返回配置、资源或 Agent 信息，不依赖某个 Runtime 已启动。可在受控网络免认证；其他方法返回 405。旧 `/apis/v1` 业务路由不保留别名或重定向。

客户端断线只释放连接和观察资源；已接纳工作继续由 Service 结算。massd shutdown 才关闭全局接纳并调用 Service 的停止协调，持续接收最终事件，尽力完成健康连接的最终通知，再关闭连接和存储。慢连接不能无限阻塞退出；未完成的释放如实报告。

## 验收

同一客户端同时观察 A/B 并发起查询：令 A 不读取直到写入失败，B 和普通 RPC 仍可继续；A 的 Agent 工作不被取消。单连接第二次 subscribe 被拒绝，取消后可重新订阅；订阅 ID 不能跨连接使用。验证 SDK 的本地慢回调同样只终止自己的观察。

验证非法消息、认证/Origin、实际代理链路、初始化竞争、退出排空和不同连接的独立性；验证两个进程使用同一目录（含路径别名）时仅一个 owner，不执行第二次启动校正。真实 Agent 场景按测试原则显式执行，离线协议验收不能替代。

[^direction]: 统一 WebSocket 的服务实例模式；观察流须能独立驱逐，连接断开不取消 Agent 工作。
[^websocket]: RFC 6455 定义消息、分片、控制帧和连接关闭；JSON-RPC 及业务顺序由 MASS 单独规定。

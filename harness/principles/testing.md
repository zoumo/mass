# 测试与验收原则

## 验证边界

优先通过模块公开接口的集成测试和端到端场景验证行为，不以单元测试数量衡量覆盖程度。模块的具体场景随各模块设计维护；本页规定所有实现共同遵守的验收原则。

离线测试验证确定性的合同，不能代替真实 Agent、模型与外部系统的验收。默认测试不调用真实模型；真实 Agent 验收必须显式执行。

替身、故障注入和观察门可以验证错误处理或控制真实操作时序，但不能伪造原生事实，再用这些事实声称真实 Agent 行为已通过验证。

## 前置条件与隔离

真实验收明确所用 Agent、可执行产物、配置与认证前置条件。前置条件缺失或场景选择为空时明确失败，不静默跳过后报告成功。

测试使用自有的临时工作区、数据目录、端口或连接资源，不读写个人运行数据。需要真实认证时，凭据由外部提供，不复制进测试证据。

测试在失败时也必须尝试清理己方资源，并核对清理结果。发送终止请求不等于资源已经释放；资源身份与释放证据的判断遵守被测组件的资源归属和生命周期合同。

## 证据与结果

保留足以定位问题的失败证据和必要观察，避免记录秘密。测试通过以实际完成且成功的场景为依据，不能仅凭测试进程启动或命令已提交判断完成。

结果绑定实际检查的源码、产物、环境与场景。记录足以识别这些输入的信息，并确认验证期间源码没有变化；发生变化时，原结果不能证明变化后版本通过。

区分通过、失败和未验证。筛选执行只证明选中且成功完成的场景；离线检查通过不证明真实 Agent 验收通过，局部验收不证明完整场景组通过。

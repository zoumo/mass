# Rust 历史实现的场景与验收清单

整理日期：2026-10-20。来源为删除前的 `mass-rs/`，可从 Git 提交
`e36d1092015a5d4fca36c1344bba3a90cecea500` 查阅原文件。

这里只备份可复用的场景、故障 case 和观察要点，不摘录实现，不保留发布检查。
本文是历史参考，不是当前设计合同；当前设计以 [harness](../harness/index.md)
为准。以下条目均未在本次整理中重新执行，不能视为当前 Go 实现已通过验收。
旧接口名、错误名、事件包装、seq、队列容量与超时数值不作为新实现要求。

## 使用与记录

- 每个 case 记录源码版本、实际 Agent 版本、运行配置、触发条件、观察和结果。
- 分别标明离线协议测试、真实 Agent 测试和未验证项；协议替身通过不证明原生行为。
- 使用独立工作目录、数据目录和端口；凭据由外部提供，证据不含秘密。
- 故障必须在可观察检查点触发，例如收到工具开始、权限请求或原生完成通知后。
- 同时观察请求回执、原生行为、公开状态、实时事件、持久历史和资源释放。
- 保留失败证据；即使断言失败也尝试清理，并读回进程身份和释放结果。
- 区分产品自身清理与测试夹具补救清理；后者不能掩盖产品资源泄漏。

## 创建、并发与失败结算

来源：`tests/scenarios/creation.rs`、`sessions/tests/lifecycle.rs`。

| Case | 前置条件与触发动作 | 检查点 |
|---|---|---|
| C01 无输入创建 | 创建 Session，暂不发送输入 | ID 来自原生返回；没有隐式输入、工具或模型工作 |
| C02 同实例并发首次创建 | 同一 Runtime 同时创建两个 Session | 不重复激活宿主；Session 身份、cwd 和事件互不串扰 |
| C03 不同实例隔离 | 相同配置的两个本地 Runtime 分别创建 Session | 运行资源各自独立；停止一方不影响另一方 |
| C04 打开失败 | 健康 Session 运行时，让另一个原生打开失败 | 健康 Session 继续工作；失败不留下假成功资源或无主运行 |
| C05 身份保存失败 | 原生已返回 ID，阻断资源身份保存 | 不能发布创建成功；清理只针对新开资源，保留原有历史 |
| C06 迟到创建结果 | 原生打开延迟到调用方超时后返回 | 保留原操作责任与名称预留；同名重试不能替换原操作；迟到 ID 被正确结算 |
| C07 配置拒绝 | 使用无效配置或不支持选项发起创建 | 在相关副作用前拒绝；不启动 Agent、不发送输入、不篡改旧数据 |

## 输入、权限、取消与旧操作隔离

来源：`tests/scenarios/cancel.rs`、`tools.rs`、`archive.rs`、
`codex/src/settlement_tests.rs`、`codex/tests/fixtures/late-tool-after-terminal.json`。

| Case | 前置条件与触发动作 | 检查点 |
|---|---|---|
| I01 工具完整链路 | 真实工具写入标记文件，再读取文件 | 工具调用、结果和最终消息关联一致；文件内容证明工具确实执行 |
| I02 权限只处理一次 | 等待权限请求，再回答或重复回答 | 授权前工具未执行；有效回答只作用一次，旧引用不能再次放行 |
| I03 流式输出期间取消 | 观察到输出增量后取消 | 接受取消不等于已终止；继续观察原工作结束，不伪造完整输出 |
| I04 工具运行期间取消 | 确认工具及其进程归属后取消 | 取消针对原工作；同时核对终止事实和己方进程释放 |
| I05 取消结果未知 | 派发取消时切断连接 | 保留未知状态，不自动重发，不将断连当作取消成功 |
| I06 迟到事件 | 原工作结束或恢复后，再到达旧工具开始/结果/权限请求 | 不改绑到新工作；旧请求不能获取新一轮授权 |
| I07 旧操作句柄 | 保存旧运行的输入、取消和配置操作句柄，关闭并恢复 Session 后调用 | 旧句柄拒绝执行，不向新的原生运行发送请求 |
| I08 宿主丢失 | 权限待答、同宿主另一个 Session 输出、输入回执未定时终止宿主 | 保留已证明的接受与历史；未知输入不重放；独立 Runtime 仍可工作 |

## 背压、协议错误与完整事实

来源：`tests/scenarios/faults.rs`、
`vendor/codex-app-server-client/MASS-README.md` 及其传输测试。

| Case | 前置条件与触发动作 | 检查点 |
|---|---|---|
| B01 慢会话 | 延迟一个 Session 的持久化，另一个 Session 正常输入 | 在容量未耗尽前，健康 Session 能继续；分别记录容量耗尽后的影响 |
| B02 大工具结果 | 工具生成带固定首尾标记的大文件并输出 | 文件与完整工具结果可核对；实时完整事实和持久历史一致 |
| B03 持续背压 | 让真实流量填满队列，再向同宿主另一 Session 输入 | 记录共享通道对 RPC/权限响应的延迟；不能宣称无限压力下完全隔离 |
| B04 数量与字节边界 | 分别用大量小事件、少量大事件施压 | 两类容量均有界；统计包括初始化积压和正在处理的事件 |
| B05 初始化积压 | 在消费者可读取前制造初始化事件溢出 | 明确失败，不能无限积压或静默丢弃完整事实 |
| B06 单事件超限 | 发送超过预算的事件、RPC 成功结果或错误结果 | 显式错误；不能截断后伪装完整事实；记录共享连接受影响范围 |
| B07 协议损坏 | 分别发送未知合法方法、已知方法的损坏载荷、无效 JSON 和超大帧 | 区分未知扩展与已知协议损坏；错误不能被当作正常完成 |
| B08 饱和时关闭 | 在队列已满、关闭命令等待接纳时请求关闭 | 总关闭期限包含排队阶段；结束后核对任务退出，不能只证明发送了关闭请求 |
| B09 预览与完整结果 | 只有增量时断流，或完整结果到达后再停止 | 不靠拼接预览制造完整历史；已接纳完整事实在关闭前结算 |

## 历史写入、损坏与读取

来源：`journal/tests/persistence.rs`、`tests/scenarios/faults.rs`、`archive.rs`。
下面保留故障类型；具体提交协议、修复入口和分页语义须按当前 Store 合同设计。

| Case | 前置条件与触发动作 | 检查点 |
|---|---|---|
| H01 追加失败 | 已有历史后，将写入目标变为不可写，再产生完整事件 | 已有历史保留；未提交事件不能作为已持久事实发布；故障会话停止接纳 |
| H02 路径修复后再操作 | 写入失败后仅修复路径，再尝试输入 | 不静默解除故障封闭；须按当前合同显式核对和恢复 |
| H03 半条尾记录 | 在完整历史后附加合法但未完成提交的记录或破损尾部 | 区分已提交前缀与未提交尾部；普通读取不擅自改写文件 |
| H04 分页外损坏 | 请求第一页，但文件后部存在损坏 | 检查并明确读取视图和损坏检测范围，不能据小页成功声称全历史完整 |
| H05 旧格式与私有字段 | 混入不支持版本或不应公开的私有材料 | 明确拒绝，保留原文件；私有材料不进入公共历史 |
| H06 身份原子替换失败 | 保存身份时制造文件替换失败 | 原文件保持完整，不留下半文件或临时文件造成假身份 |
| H07 恢复后前缀不变 | 保存历史快照，关闭/恢复后发送新输入 | 旧事件内容、身份和顺序不变；新增事件追加，旧业务动作不重放 |

## 关闭、恢复与归属

来源：`tests/scenarios/archive.rs`、`faults.rs`、`codex/src/recovery.rs`。

| Case | 前置条件与触发动作 | 检查点 |
|---|---|---|
| L01 不同工作阶段关闭 | 分别在 idle、输出中、权限待答和输入排队时关闭 | 封闭新接纳；结算原工作与事件；不放行尚未授权工具，不影响健康同伴 |
| L02 关闭超时与迟到释放 | 原生释放晚于关闭期限，再重复关闭并观察迟到通知 | 未知结果不变成已释放；原清理责任保留；迟到通知不重新打开接纳 |
| L03 同宿主与冷恢复 | 分别在宿主仍在、进程重启后恢复 | 身份不变且无隐式输入；冷恢复额外验证账号、配置与数据归属 |
| L04 归属不匹配 | 更换 provider、认证来源、账号或数据目录 | 拒绝冒认原会话，不以同名/相同 URL/相同 ID 代替归属证据，不创建替代 Session |
| L05 无法证明冷恢复 | 原认证模式或恢复材料不足以核对归属 | 明确拒绝恢复；已有离线历史仍可读取，不擅自改写材料 |
| L06 停止期间排空 | 分别在只有预览、原生完整结果已到但未提交时停止 | 不制造预览完成；已接纳完整事实持久结算；核对宿主和己方后代进程释放 |

## 远端连接与共享服务

来源：`tests/scenarios/remote.rs`、`tests/remote.rs`。

| Case | 前置条件与触发动作 | 检查点 |
|---|---|---|
| R01 独立远端连接 | 两个 Runtime 连接同一外部服务并分别创建 Session | ID 来自各连接的原生响应；会话事件与输入不串扰 |
| R02 停止一方 | 一方有活动工具时停止其 Runtime，另一方继续输入 | 只释放己方连接和任务；外部服务仍存活，同伴仍能完成工作 |
| R03 断连中的取消/关闭 | 活动工作期间使取消响应和连接失效 | 本地连接关闭不能证明远端工作终止；缺少释放证据时保留未知责任 |
| R04 不支持跨连接恢复 | 对未声明恢复能力的远端 Session 请求恢复 | 在重新连接或修复数据前拒绝；旧历史不变，不偷偷发起原生恢复 |
| R05 远端认证边界 | 配置含凭据地址、不安全传输或缺失秘密引用 | 拒绝非法配置或激活；不回退宿主其他凭据，不在错误和证据中泄露秘密 |

历史远端原生场景使用无认证回环服务；它不能证明真实远程部署的认证、WSS
证书或账号隔离已经通过。测试拥有的外部服务只能由夹具在同伴存活断言完成后清理。

## 事件处理器隔离

来源：`tests/scenarios/handlers.rs`、`events/tests/handlers.rs`。

| Case | 前置条件与触发动作 | 检查点 |
|---|---|---|
| E01 慢或失败处理器 | 单个处理器阻塞、报错或 panic，同时观察同伴 | 区分处理器故障与 Agent 故障；历史不被改写，记录对其他处理器/会话的影响 |
| E02 修改本地副本 | 处理器修改收到的事件副本 | 不影响原事件、其他消费者或持久历史 |
| E03 处理器重入 | 处理器收到事件后发起输入，同时关闭或恢复原会话 | 不死锁；操作仍绑定原运行，过期句柄不能作用于新运行 |

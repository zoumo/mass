# 语言无关编码原则

这些原则适用于所有语言实现，用于开发决策与代码审查。

## 清晰

- 代码表达做什么，以及必要的原因。
- 使用含义明确的名称，优先清晰而非简短。
- 优先直观、从上到下可读的表达，避免炫技。

## 简单

- 优先标准工具，减少自定义机制。
- 避免不必要的抽象层级。
- 使用能满足要求的简单方案，避免过早优化。

## 简洁

- 提高有效信息占比，不用注释重复代码。
- 使用语言惯用写法，并突出重要约束。

## 可维护

- 代码应易于正确修改。
- 明确假设和关键细节，避免隐藏约束。
- 保持命名可预测，尽量减少依赖。

## 一致

- 遵循已有模式。
- 局部约定不得破坏整体清晰性。
- 不以风格调整加重已有问题。

## 避免重复

- 避免重复逻辑。
- 只有复杂性确实需要时才引入抽象。
